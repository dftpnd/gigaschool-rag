## Конфигурации контекста

- **baseline retrieval** — топ-5 baseline КТ 3: BGE-M3 + BM25 (k1 = 0,3, b = 1,0), взвешенная сумма alpha = 0,6,
  фильтр по патчу из запроса.
- **best retrieval** — топ-5 лучшей конфигурации КТ 4: тот же поиск + LLM-реранкер listwise (промпт v2 «оценки 0–2
  всей пачке»), пул 20. Ответы реранкера берутся из кэша КТ 4: контекст — артефакт КТ 4, номера чанков сохранены
  в `gold/kt5_answers.jsonl`.

У половины вопросов (25 из 50) набор топ-5 в двух конфигурациях одинаковый. Чанки — с префиксом метаданных
(заголовок, тип, патч, дата), как в КТ 3–4.

## Генерация

**Модель** — `deepseek-flash` (DeepSeek-V4.1-Flash), t = 0, seed 42, `thinking: disabled`; та же, что у реранкера
КТ 4. **Промпт** — `gigarag.generation.SYSTEM`, версия 1, без изменений на всё КТ 5:
- отвечать только по фрагментам, не по собственным знаниям об игре;
- если ответа во фрагментах нет — ровно «Не знаю: в найденных материалах нет ответа.» (так же — если фрагменты
  про другую сущность или другой патч);
- если ответ есть на часть вопроса — ответить на неё и сказать, какой части нет;
- использовать все фрагменты, относящиеся к вопросу, и ставить номер фрагмента после каждого утверждения.

Отказ распознаётся без LLM — по началу ответа (`patterns.is_abstention`). Стоимость — 1 429 входных и 116 выходных
токенов на ответ, $0,57 на 1000 ответов; медиана ответа API — 1,17 с.

**Отказы по типам вопросов**, %:

| | factual | composite | abstract | negative |
|---|---|---|---|---|
| baseline retrieval | 6,7 | 0,0 | 40,0 | **100** |
| best retrieval | 0,0 | 6,7 | 40,0 | **100** |

Проверка на негативных пройдена. Ложные отказы почти все на абстрактных вопросах: модель не находит ответа
на «как менялось отношение сообщества к …» в пяти отдельных постах.

## LLM-судья

**Три критерия — три отдельных запроса** (`gigarag.judge`), шкала 1–5 с описанием каждого балла:
- **faithfulness** — подтверждается ли каждое утверждение ответа фрагментами;
- **answer relevance** — отвечает ли ответ на вопрос;
- **context utilization** — использует ли ответ всю относящуюся к вопросу информацию из фрагментов.

Судья видит вопрос, фрагменты и ответ, но не эталон gold. **Отказ** оценивается по тому, есть ли ответ
в контексте: достоверность — 5; релевантность и использование — 5, если ответа во фрагментах нет, и 1, если есть.
Шкалы (`judge.SCALES`) одни и те же во всех версиях промпта и на странице ручной разметки. Модель судьи —
`deepseek-flash` без рассуждения, t = 0.

**Достоверность публикуется долей достоверных ответов** (балл ≥ 4), а не средним. Контроль на искажениях
проверяет именно эту границу. Калибровку внутри ошибок он не проверяет: в прошлом прогоне судья поставил 1
там, где по шкале 3.

### Выборки

Выборки делятся по вопросам, на каждый вопрос — один ответ, конфигурация выбирается случайно. Оценка разметки
хранится с хэшем того, что видел человек (вопрос, фрагменты, ответ): изменившийся ответ теряет оценку.

| Выборка | Что в ней | Для чего |
|---|---|---|
| **dev** | 30 вопросов, ручная разметка | итерации промпта, детерминизм, выбор версии |
| **контроль dev** | 21 подтверждённый ответ dev + 40 искажений | проверка достоверности при выборе версии |
| **holdout** | 20 других вопросов, не участвовавших в подборе промпта ни в одном прогоне; разметка после заморозки | итоговая kappa |
| **контроль holdout** | 14 подтверждённых ответов holdout + 26 искажений | итоговая проверка достоверности |

### Итерации промпта и детерминизм

Версии v1–v4 создавались на прошлом прогоне ответов. После ревью все ответы и все версии судьи пересчитаны
одним свежим прогоном, v5 сделана на новом dev. 30 ответов dev оцениваются дважды: второй прогон — с отдельным
кэшем, модель отвечает заново.

| Версия | Что меняет | Faithfulness | Relevance | Utilization |
|---|---|---|---|---|
| v1 | шкала + короткое обоснование | 96,7% | 93,3% | 90,0% |
| v2 | свободный разбор + правила пограничных случаев | 96,7% | 90,0% | 96,7% |
| v3 | короткие структурированные поля вместо разбора | 100% | 96,7% | 93,3% |
| v4 | правило противоречия для достоверности | 100% | 96,7% | 93,3% |
| **v5** | правило «ответ во фрагментах есть — только прямой ответ» | **100%** | **93,3%** | **100%** |

Ответов не по формату — 0 у всех версий. Порог 85% проходят все.

**Что было не так и как исправлено** (полный список расхождений с обоснованиями — в разделе 4 ноутбука;
примеры 1–6 — из прошлого прогона, на котором делались v1–v4):

1. **v1 → v2, faithfulness.** Ответ связал два факта, которые фрагменты не связывают (q15), и прогоны ставили
   то 4, то 5: «незначительная неточность» не определена. В v2 это явное правило: связка, которой нет
   во фрагментах, — не выше 4.
2. **v1 → v2, faithfulness.** Два фрагмента противоречат друг другу (q08), ответ передаёт оба. Правило v2: верная
   передача противоречащих фрагментов — не ошибка.
3. **v1 → v2, relevance.** Ответ на одну часть вопроса и честное «второй части нет» (q26): 4 или 3? Правило:
   часть без ответа не считается отвеченной — 3.
4. **v1 → v2, relevance.** Вторая часть вопроса «закрыта» цитатами не по теме (q30). Правило: такие цитаты
   часть не закрывают.
5. **v1 → v2, utilization.** Что считать «относящимся к вопросу» (q04, q37). Правило: только то, о чём спрашивают.
6. **v2 → v3.** Свободный разбор каждый раз уводит рассуждение в другую сторону: в прошлом прогоне релевантность
   v2 повторялась в 80% случаев, два ответа не разобрались как JSON. v3 заменила разбор короткими полями.
7. **v3 → v4, faithfulness.** Найдено контрольной выборкой: v3 считала неверное число «неточностью пересказа»
   и ставила 4. В v4 противоречие фрагментам — отдельное поле и правило.
8. **v4 → v5, relevance и utilization.** На новом dev v4 ставила 1 честным отказам на абстрактных и негативных
   вопросах (q37–q40, q48), где во фрагментах лишь разрозненные упоминания темы, а в «нужные факты» вписывала
   то, чего во фрагментах нет (q29). Правило v5: «ответ во фрагментах есть» — только если фрагменты прямо отвечают
   на вопрос.

## Проверка судьи достоверности на искажённых ответах

Человек ставит достоверность 5 почти всем ответам: на такой выборке судья, всегда ставящий 5, неотличим
от хорошего. **Контрольная выборка** (`gigarag.perturbation`) — ответы, которые человек признал достоверными,
и две их копии:
- **число заменено** — одно значение ответа заменено другим, которого нет ни в одном фрагменте;
- **добавлен факт** — дописано правдоподобное утверждение со ссылкой [1] и числом, которого нет во фрагментах.

Метка — по построению: исходный ответ достоверен, искажённый — нет. «Поймал» — балл ≤ 3.

| Контроль dev | Ложная тревога на исходных | Поймано: число заменено | Поймано: добавлен факт | κ |
|---|---|---|---|---|
| v1 | 4,8% | 36,8% | 85,7% | 0,50 |
| v2 | 0,0% | 21,1% | 100% | 0,53 |
| v3 | 0,0% | 42,1% | 100% | 0,64 |
| v4 | 4,8% | **100%** | **100%** | **0,96** |
| **v5** | 4,8% | **100%** | **100%** | **0,96** |

v1–v3 ловят выдуманный факт, но заменённое число считают неточностью. **Контроль holdout** (v5 заморожена):
ложных тревог — 0 из 14, поймано 12 из 12 и 14 из 14, κ = 1,0.

## Валидация человеком

**Разметка** — через локальную страницу (`scripts/kt5_annotate.py dev|holdout`). Человек видит то же, что судья,
и те же шкалы; конфигурация, эталон и оценки судьи скрыты. Оценки прошлого прогона перенесены только на ответы,
совпавшие дословно (хэш содержимого): 6 из 30 в dev и 2 из 20 в holdout. Остальные размечены заново.

**Выбор версии** — среди прошедших порог детерминизма та, у которой выше средняя kappa на dev по трём критериям:
для релевантности и использования — против человека, для достоверности — против меток контроля dev.

| dev | κ relevance | κ utilization | κ faithfulness (контроль) | Среднее |
|---|---|---|---|---|
| v1 | 0,68 | 0,03 | 0,50 | 0,41 |
| v2 | 0,47 | 0,37 | 0,53 | 0,46 |
| v3 | 0,36 | −0,02 | 0,64 | 0,33 |
| v4 | 0,36 | −0,02 | 0,96 | 0,44 |
| **v5** | 0,48 | −0,00 | 0,96 | **0,48** |

Выбрана **v5**. Она заморожена коммитом `69b9fd5` до разметки holdout.

**Итоговая проверка v5** — weighted kappa (квадратичные веса, `stats.weighted_kappa`, сверено со sklearn):

| | Критерий | κ с человеком | Точно | ±1 балл |
|---|---|---|---|---|
| dev (подбор) | faithfulness | −0,03 | 93,3% | 96,7% |
| | relevance | 0,48 | 70,0% | 93,3% |
| | utilization | −0,00 | 96,7% | 100% |
| **holdout** | faithfulness | не определена | 100% | 100% |
| | relevance | **0,29** | 75,0% | 85,0% |
| | utilization | 0,00 | 95,0% | 95,0% |

- **Relevance: κ 0,29 на holdout — судья по этому критерию ненадёжен.** По заданию промпт нужно переработать
  и проверить на новой независимой разметке с κ ≥ 0,4; в КТ 5 это не сделано. До этого релевантность не используется
  в сравнительных выводах: разница между конфигурациями может быть следствием систематической ошибки судьи.
  Расхождения в основном в одну сторону: на 4 ответах человек ставит 5, судья — 1–4. Судья строже засчитывает
  «часть вопроса отвечена».
- **Utilization и faithfulness: kappa с человеком не информативна.** Человек поставил 5 всем ответам holdout,
  и при постоянной оценке одного оценщика kappa равна 0 (или не определена) при любом согласии; точное совпадение —
  95% и 100%. Faithfulness проверен контролем (κ = 1,0). Использование контекста у v5 — 5,0 почти у всех ответов:
  после правила v5 критерий почти перестал различать ответы.
- **Ограничения.** Разметчик один. Контрольные искажения синтетические: одно число, один шаблонный факт.

## Воспроизводимость модели

У DeepSeek нет неизменяемого ID версии: `/models` отдаёт алиас `deepseek-flash` (DeepSeek-V4.1-Flash), который
обновляется на сервере. Даже при t = 0 и одном fingerprint повторный прогон генерации совпал с прошлым дословно
лишь у 45 ответов из 100. Поэтому:
- **КТ 5 — один свежий прогон в своём кэше** (`data/llm_cache/kt5/`). У всех 100 ответов генерации и 300 вердиктов
  судьи записаны `model`, `system_fingerprint` (`bc19ba97cbe016479903222bb1578db6`) и id ответа API.
- **Результаты лежат в git как артефакт эксперимента.** `gold/kt5_answers.jsonl` — ответы с номерами чанков
  контекста и идентичностью модели, `gold/kt5_verdicts.jsonl` — все вердикты финального судьи. Разметка —
  `gold/kt5_labels_dev.json` и `gold/kt5_labels_holdout.json` с хэшами содержимого. Выводы проверяются
  по этим файлам без вызовов API.
- **Разметка привязана к содержимому.** При перегенерации изменившиеся ответы теряют оценки, и расчёт
  останавливается.
- **Кэш LLM и выборки разметки** (`data/`) — вне git: в них тексты корпуса.

## Вывод для финального отчёта

- **Ответы достоверны и честно отказываются:** 97% достоверных ответов, 100% отказов на негативных — оба показателя
  проверены (контроль κ = 1,0).
- **Абстрактные вопросы не решены:** R@5 12,9% у baseline и 22,4% у best (КТ 4), 40% ложных отказов.
  Следующий шаг — не реранкинг, а генерация с синтезом по многим фрагментам (map-reduce или агент с несколькими
  поисками).
- **Качество ответа по релевантности не измерено надёжно** — нужна новая версия промпта судьи и новая независимая
  разметка с κ ≥ 0,4.
- **Судья:** достоверность — надёжна (контроль κ = 1,0); релевантность — ненадёжна (κ 0,29 на holdout), выводы
  по ней предварительные; использование контекста у v5 насыщено. Следующая итерация судьи — релевантность
  частичных ответов, на новой разметке.
- **Какую конфигурацию брать.** Best retrieval — по проверенным метрикам: выше R@5 и NDCG@5 при той же доле
  достоверных ответов и том же поведении на отказах. Цена — +1,2 с на запрос: поиск 1,27 с против 0,05 с,
  генерация у обеих ≈ 1,2 с.

## Решения по ходу КТ

- **Генератор и судья — `deepseek-flash` без рассуждения.** Риск — судья оценивает ответы своей же модели;
  holdout и контроль проверяют, насколько это мешает.
- **Судья без эталона gold** — критерии задания про связь ответа с контекстом, правильность по эталону мерили
  в КТ 1 (baseline без RAG).
- **Шкалы вынесены в общую константу** — промпт судьи меняется от версии к версии, шкала для человека и судьи нет.
- **После ревью:**
  - добавлен контроль достоверности на искажённых ответах (v4);
  - подбор отделён от проверки, выборки разделены по вопросам;
  - разметка привязана к хэшу содержимого;
  - всё пересчитано свежим прогоном с записью идентичности модели;
  - достоверность публикуется долей достоверных, а не средним;
  - выборки с текстами корпуса убраны из git, история ветки переписана.
- **Продвинутый RAG не делался** — дедлайн КТ 5 совпал с днём работы.

| `gigarag.generation` | промпт генерации, контекст из пронумерованных фрагментов, запрос |
| `gigarag.judge` | шкалы трёх критериев, версии промпта судьи, разбор вердикта, оценка набора ответов |
| `gigarag.perturbation` | искажения ответа и доля пойманных искажений для контроля достоверности |
| `gigarag.annotation` | выборки и страница ручной разметки, оценки с хэшем содержимого |
| `gigarag.llm` | + идентичность модели в ответе: `model`, `system_fingerprint`, id |
| `gigarag.stats` | + weighted Cohen's kappa, доля совпадений ±k |
| `scripts/kt5_annotate.py` | локальный веб-сервер разметки: адрес на каждый ответ, сохранение каждой оценки |

Тесты — `tests/test_kt5_library.py`.
