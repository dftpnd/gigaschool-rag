# КТ 3 — Векторная база, эмбеддинги и sparse/dense/hybrid поиск

Текст задания со страницы курса «LLM-инженер» (GigaSchool). Дедлайн: 14 октября.

КТ 3 начинается с фиксации baseline: явно указать, какой чанкер и параметры предобработки выбраны по итогам
КТ 2 и почему. Это решение больше не пересматривается.

## Векторная БД

Выбрать одну БД из Milvus, Qdrant или ChromaDB — и сравнить 2–3 конфигурации индекса, а не запускать
с настройками по умолчанию.

Для каждой конфигурации замерить четыре показателя:

- Время индексирования всего корпуса,
- Медианное время одного запроса (по 100 запросам),
- Пиковое потребление RAM при индексировании,
- Recall@5 на gold_dataset — чтобы видеть, что теряем в качестве при ускорении.

Scalability — отдельный эксперимент: проиндексировать 10% / 25% / 50% / 100% корпуса и показать графиком,
как меняется время запроса и память. Это покажет, насколько выбранный индекс применим при росте данных.

Идея: не «какой индекс лучше», а «какой trade-off между точностью, скоростью и памятью оптимален для данного
корпуса и продакшн-сценария».

## Эмбеддинг-модели

Взять минимум три модели разного размера из MTEB RU leaderboard — важно, что выбор обоснован, а не случаен.

Логика выбора должна покрывать разные точки trade-off:

- Лёгкая (< 100M параметров) — для понимания нижней границы качества при минимальных затратах,
- Средняя — основной кандидат, баланс качества и скорости,
- Тяжёлая (топ MTEB RU) — верхняя граница качества, точка отсчёта (отталкивайтесь от максимального
  допустимого для вас и проекта размера модели).

Для каждой модели зафиксировать в одной таблице: размер модели (МБ), время эмбеддинга всего корпуса, время
одного запроса, метрики ретрива на gold_dataset, MTEB RU score из leaderboard.

Важный момент про MTEB score: явно ответить на вопрос — коррелирует ли позиция в MTEB leaderboard с качеством
на вашем конкретном корпусе? Если нет — объяснить почему. Возможно, какая-то из моделей лучше справляется
с запросами, содержащими специфичную лексику: например, для биохимического корпуса лучше подойдёт модель,
предобученная на биохимических данных.

## Три пайплайна поиска

Все три оцениваются на одном gold_dataset по одним метрикам: Precision@k, Recall@k, NDCG@k при k = 1, 5, 10.

### Sparse — BM25

- Реализовать через rank-bm25.
- Параметры: перебрать k1 и b, обосновать выбор границ интервалов значений, выбрать лучшую комбинацию
  и обосновать.
- Зафиксировать: время индексирования, время запроса, метрики при лучших параметрах.

### Dense

Это не новый эксперимент — применить уже найденные оптимальные настройки из предыдущих разделов:
лучшую модель + лучшую конфигурацию индекса. Важно это явно показать как осознанное решение, а не случайный выбор.

### Hybrid

Самая исследовательская часть — нет правильного ответа, есть обоснованный выбор.

Реализовать и сравнить два метода слияния:

- Reciprocal Rank Fusion (RRF) — надёжный baseline, не требует подбора весов.
- Weighted linear combination — перебрать alpha для dense части, найти оптимум.

Для финальной конфигурации hybrid обязательно ответить на вопрос: при каких типах вопросов из gold_dataset
(фактические / составные / негативные / абстрактные) hybrid выигрывает у каждого компонента по отдельности
и почему. Это требует разбивки метрик по типам, а не только агрегированных цифр.
