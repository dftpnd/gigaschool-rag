# КТ 1 — корпус и золотой набор

Тема корпуса — **изменения баланса Dota 2**: официальные патчноуты и то, как их пересказывают
и обсуждают игроки. Язык — русский (эмбеддеры в КТ 3 выбираются из MTEB RU).

| Шаг | Статус | Где |
|---|---|---|
| Сбор сырых данных | ✅ | `scripts/fetch_*.py` |
| Сборка корпуса | ✅ | `scripts/build_corpus.py` → `data/corpus.jsonl` |
| EDA | ✅ | `eda.ipynb` (исходник — `eda.py`) |
| Золотой набор | ✅ | `scripts/build_gold.py` → `gold/gold.jsonl`, описание — `gold.ipynb` (исходник — `gold.py`) |

| Baseline LLM без RAG | ✅ | `scripts/baseline_no_rag.py` → `gold/baseline_no_rag.jsonl`, разбор — `gold.ipynb` |

## Воспроизведение

**Окружение.** Python 3.12+, зависимости — через [uv](https://docs.astral.sh/uv/) из корня репозитория:

```bash
uv sync
```

На Linux ставится PyTorch с CUDA 12.8 (проверено на RTX 5080), на macOS и других платформах — обычная
сборка PyTorch с PyPI. GPU не обязателен: ноутбук сам выбирает `cuda`, если он доступен, иначе `cpu`.
На CPU единственный тяжёлый шаг — эмбеддинги для кластеризации (~21 тыс. коротких текстов): он займёт
заметно дольше, чем на GPU (на RTX 5080 весь ноутбук исполняется меньше чем за минуту с холодным кэшем).

**Данные и корпус:**

```bash
cd kt1-corpus-gold/scripts
../../.venv/bin/python fetch_patches.py
../../.venv/bin/python fetch_dota2ru.py
../../.venv/bin/python fetch_telegram.py Dota2 gabenews --since 2022-01-01
../../.venv/bin/python build_corpus.py   # печатает sha256 собранного корпуса
```

**EDA** — исполнить ноутбук из папки `kt1-corpus-gold` (исходник `eda.py` синхронизирован через jupytext):

```bash
cd kt1-corpus-gold
../.venv/bin/jupytext --to ipynb eda.py
../.venv/bin/jupyter nbconvert --to notebook --execute --inplace eda.ipynb
```

**Золотой набор и baseline** — стадии по очереди (нужен `OPENAI_API_KEY` в `.env` в корне), затем ноутбук:

```bash
cd kt1-corpus-gold/scripts
for stage in generate stylize label review finalize; do ../../.venv/bin/python build_gold.py $stage; done
../../.venv/bin/python baseline_no_rag.py
cd .. && ../.venv/bin/jupytext --to ipynb gold.py && ../.venv/bin/jupyter nbconvert --to notebook --execute --inplace gold.ipynb
```

Ответы LLM кэшируются в `data/llm_cache/` по полному запросу (модель, промпты, температура, seed):
повторный прогон воспроизводит набор без обращений к API. Решения ручного ревью — `gold/review.json`;
стадия `finalize` читает их и не требует LLM.

**Детерминизм.** Сборка корпуса не зависит от порядка файлов на диске и от `PYTHONHASHSEED`: все списки
файлов сортируются, выборка офтопа делается из популяции, отсортированной по `doc_id`, генератором
с seed на канал, id комментариев без собственного номера — стабильный digest `blake2b`.
Уникальность `doc_id` проверяется при сборке. На снимке от 25.10.2026 sha256 корпуса —
`76b0676b841020e9c3917d56f745ca1559e5cf35556ee1cf1b5352b5f0e0ea73`.
Кэши EDA (`data/cache/`) привязаны к sha256 корпуса, параметрам расчёта и отпечатку исходного кода
функций, от которых зависит результат: после пересборки корпуса или правки правил они не подхватываются,
а пересчитываются. KMeans запускается в однопоточном режиме: в многопоточном sklearn даёт разные метки
от запуска к запуску даже при фиксированном seed. Два прогона ноутбука подряд дают одинаковые выводы.

Модели Hugging Face закреплены по commit SHA (`revision=`), ревизии входят в ключи кэшей:

| Модель | Зачем | Ревизия |
|---|---|---|
| `BAAI/bge-m3` | токенизатор для длин и доли шума | `5617a9f61b028005a4858fdac845db406aefb181` |
| `intfloat/multilingual-e5-small` | эмбеддинги для кластеризации | `614241f622f53c4eeff9890bdc4f31cfecc418b3` |

Скачано 25.10.2026: 118 патчей, 134 статьи с 16 тыс. комментариев, 18,2 тыс. постов @Dota2
(с 01.2022) и 25,7 тыс. постов @gabenews (с 08.2023, начало канала).

## Решения при сборке корпуса

1. **Окно — патчи 7.34+ (август 2023 — октябрь 2026).** За этот период есть все четыре источника,
   поэтому одни и те же изменения описаны и официально, и в пересказах, и в обсуждениях.
   Скачано было в ~15 раз больше минимума ТЗ; полный объём сделал бы LLM-обработку и
   эксперименты КТ 2–5 непропорционально дорогими.
2. **Документ патчноута — блок «сущность в патче»** (герой, предмет, нейтральный предмет,
   общие изменения), а не весь патч: так ответ на фактический вопрос лежит в одном документе.
   Блоки с `ability_id = -1` — общие примечания раздела предметов, названы «Предметы: общее».
3. **Статья и каждый комментарий — отдельные документы.** Комментарий хранит ссылку на статью
   (`meta.article_id`) — это пригодится как метаданные в КТ 2.
4. **Telegram — только посты по теме плюс 20% офтопа.** Тематичность — регулярка по терминам
   баланса (патч, нерф, баф, аспект, талант…), английским именам героев и предметов
   из справочников dota2.com и русским/сленговым именам (Пудж, бкб, аган…).
   Из нетематических постов случайно берётся 20% от числа тематических — как реалистичный шум
   (seed `42:<канал>`, популяция отсортирована по `doc_id`).
   Каждая основа термина привязана к началу слова (`\bап\b`, `\bульт`, `\bмет[аеуы]\b`): в первой версии
   словаря «ап» срабатывал внутри «этап», «сетап», «кейкап», «ульт» — внутри «результат», «мета» — внутри
   «предмета». Исправление (по ревью PR) убрало из тематических 1 105 постов (5 804 → 5 491 в @Dota2,
   6 543 → 5 751 в @gabenews), офтоп пропорционально сократился; корпус — 20 990 → 19 665 документов,
   EDA и все цифры ниже пересчитаны.
5. **Никакой чистки.** HTML-разметка, эмодзи, ссылки, шаблонные подписи и дубликаты остаются:
   чистка и её эффект — задача КТ 2.

Формат `data/corpus.jsonl`: `doc_id`, `source`, `date`, `patch`, `url`, `title`, `text` (сырой текст/HTML), `meta`.

## EDA — коротко

Подробно — в `eda.ipynb`, раздел «Выводы».

Видимый текст — сырой текст без тегов и с декодированными HTML-сущностями (`&nbsp;` → пробел).

- Медиана — 58 токенов, 41,1% документов короче 50; длиннее 2000 — 33 документа (30 статей и 3 блока патчноутов).
- Удаляемый шум (HTML-теги и сущности, URL, эмодзи, декоративные спецсимволы) — 82,5% токенов BGE-M3
  сырого корпуса, почти весь — HTML (79%). Числа (1,1% корпуса, 11% патчноутов) и пунктуация шумом не считаются:
  в патчноутах числа — суть правки.
- 2,2% лишних точных копий и 1,6% документов (167 пар) в почти-дубликатах. Кандидаты — MinHash LSH
  с порогом 0,5, каждая пара проверяется точным Jaccard ≥ 0,8 по словесным 3-граммам; число подтверждённых
  пар выходит на плато уже с порога 0,6, при пороге LSH 0,8 нашлось бы только 156.
- Кластеры (ключевые слова — c-TF-IDF): правки баланса, пересказы патчей, выход обновлений, турниры,
  интервью и про-игроки, винрейты, баги и механики, косметика, розыгрыши и промо, обсуждения и реакции форума.
- Скрытая реклама: регулярка по букмекерским словам находит ~1% постов, но отдельный кластер
  розыгрышей и промо бота-предиктора — ~1,6 тыс. постов.
- Главные риски для ретрива: разнородные длины, HTML, один факт в нескольких источниках,
  английские имена в патчноутах против русского сленга в постах, одна сущность во многих патчах.

## Золотой набор

50 вопросов в `gold/gold.jsonl`: 15 фактических, 15 составных, 10 абстрактных, 10 негативных.
Подробности, таблицы и графики — в `gold.ipynb`.

Формат строки: `qid`, `qtype`, `question`, `answer`, `evidence` (список `passage_id`, `doc_id`, `grade`,
`quote`), `split`, `styles`, `original_question` (формулировка до стилизации), `seed_docs`.
Релевантность размечена на уровне **отрывков**: короткий документ — один отрывок, статья dota2.ru —
разделы по заголовкам HTML, не длиннее 1 500 символов (`gigarag.passages`). Обход DOM рекурсивный:
весь видимый текст статьи попадает в отрывки ровно один раз, это проверяется при нарезке. Слишком длинный
блок режется по предложениям, затем по словам. Оценка 2 — отрывок содержит
ответ или его необходимую часть, 1 — по теме, но без ответа. `quote` — дословная цитата из отрывка:
по ней релевантность переносится на любые чанки КТ 2, как бы ни резался документ.

### Как построен

Набор построен с помощью LLM в пять стадий (`scripts/build_gold.py`), с ручным ревью в конце.

1. **Затравки** (`gold_seeds.py`, seed 42) — документы, по которым генерируется вопрос. Затравок
   на ~50% больше квот: часть кандидатов отсеется на ревью.
   - Фактические: блок патчноута с числовой правкой («с X до Y»), по одному на патч по кругу, — 16;
     тематический пост Telegram с числами — 6.
   - Составные: два патча одной сущности — 8; правка и пост Telegram о ней в течение 30 дней — 7;
     правка и комментарий к статье того же патча — 7.
   - Абстрактные: общие изменения крупного патча — 4; комментарии к статье патча — 5;
     посты на тему (нейтралки, аспекты, винрейты, staging, баги) — 5.
   - Негативные — по видам: патч до окна корпуса — 4, будущий патч — 3, несуществующая сущность — 3,
     ложная предпосылка — 4, другая игра — 2.
2. **Генерация** — вопрос, эталонный ответ и дословные цитаты из затравок. Генератор знает охват корпуса
   (патчи 7.34–7.41f), чтобы негативные вопросы действительно были вне его.
3. **Стилизация** — для лексического разнообразия часть вопросов переписана отдельным запросом
   по циклу стилей (seed `42:styles`). Исходная формулировка сохранена в `original_question`.
4. **Разметка** — для каждого кандидата собираются отрывки-кандидаты, судья оценивает каждый
   отдельным запросом. Отрывки — объединение топ-10 трёх поисковиков (BM25, `multilingual-e5-small`,
   `bge-m3`) по вопросу, исходной формулировке и эталонному ответу; не больше 40, плюс все отрывки
   затравок. Три поисковика разной природы нужны, чтобы разметка не подыгрывала одному методу КТ 3.
   Всего 2 833 пары «вопрос × отрывок», в среднем 38 на вопрос. Оценка 2 ставится только по смыслу
   вопроса: тот же герой, патч, человек; совпадения названия с эталоном недостаточно. Цитата судьи
   проверяется на вхождение в отрывок. Если её там нет, судью переспрашивают (76 раз); если дословной
   цитаты нет и после этого, оценка снимается, а случай получает флаг на ревью (5 отрывков).
5. **Ревью** — автоматические флаги и ручной просмотр каждого кандидата. Флаги:
   - судья не подтвердил затравку; цитата генератора не найдена в документе;
   - у негативного вопроса найден ответ; дубль вопроса по Jaccard биграмм ≥ 0,6;
   - оценка снята из-за непроверенной цитаты;
   - **оценка 2 у отрывка из другого патча**, чем назван в вопросе;
   - подсказка: слова ответа, основы которых нет ни в одном доказательстве (так ловится неверно раскрытый
     сленг).

   Решения с причинами — `gold/review.json`: `accept`, `reserve` (годен, но сверх квоты) или `reject`.
   Каждое решение хранит digest того, что видел ревьюер (вопрос, ответ, затравки, разметка): если
   кандидат изменился, финализация останавливается и требует нового ревью.

   Главная ошибка судьи — оценка 2 правке той же сущности из соседнего патча («Bane в 7.37b» ←
   правка таланта из 7.34). Строгий промпт её не устранил, флаг «другой патч» находит. Ревьюер исправил
   42 оценки у 22 кандидатов: 39 понижены (в основном до 1), 3 восстановлены с дословной цитатой.
   Ещё поправлены формулировки:
   - q01 спрашивал абсолютный базовый урон, а патчноут даёт только «уменьшен на 3» — вопрос
     переформулирован в «как изменился»;
   - в эталоне q28 сленговый «нулик» был раскрыт как Nullifier, а это Null Talisman — исправлено;
   - c056: «за рассматриваемый период» заменено на «в 2023–2026 годах».

   При финализации отрывки короче 40 символов («+1», «100%») не считаются доказательством.
   Проверяются инварианты: у негативного вопроса нет отрывков с оценкой 2, у остальных они есть;
   у каждого размеченного отрывка есть дословная цитата из него.

**Модели и параметры** (`scripts/gold_prompts.py`, версия промптов 2, seed API 42):

| Шаг | Модель | Температура | Зачем такая |
|---|---|---|---|
| Генерация вопросов | `gpt-4.1-2025-04-14` | 0,7 | разнообразие формулировок |
| Стилизация | `gpt-4.1-2025-04-14` | 0,9 | переписывание в стиле требует вариативности |
| Разметка релевантности | `gpt-4.1-2025-04-14` | 0 | разметка должна быть детерминированной |

Промпты целиком — в `gold_prompts.py`. Главные правила генератора: вопрос звучит как вопрос игрока,
а не пересказ документа; ответ однозначно следует из документов, без внешних знаний; на каждый документ —
дословная цитата 5–40 слов; без вопросов «да/нет». Тип вопроса задаётся отдельной инструкцией. Например,
составной вопрос — «ответ требует объединить информацию из обоих документов, ни один по отдельности
не даёт полного ответа». Судья оценивает только по тексту отрывка, без внешних знаний, и приводит цитату.

### Отклонённые вопросы

Из 74 кандидатов принято 50, 12 в резерве сверх квоты, 12 отклонено. Все причины — в `gold.ipynb`
и `gold/review.json`; характерные примеры:

| Кандидат | Вопрос | Причина |
|---|---|---|
| c030 | Какие изменения произошли с героем Primal Beast в патче 7.37e и как игроки используют новые игровые функции, чтобы играть против этого героя? | Искусственная связка: пост о «Лаборатории» не связан с правкой героя. Типичная беда составных вопросов из случайной пары документов |
| c026 | Как изменялась эффективность Blood Rite у Bloodseeker в патчах 7.36b и 7.39d…? | Цитата генератора не найдена в документе, значения в ответе не подтверждаются отрывками: эталон может быть галлюцинацией |
| c017 | Йо, в 7.39d кто сейчас топовые оффлейн-коры? Топ-3 имбы на тройку кто ща? | Ответ взят из одного еженедельного мета-отчёта, другие отчёты того же патча дают другие списки: эталон неустойчив |
| c050 | как игроки вобще воспринлип изменения в баллнсе в патчах дота2 за этот пеиод… | «Этот период» без контекста: для реального пользователя вопрос бессмыслен |
| c049 | Какие основные настроения и тренды можно выделить в обсуждениях дотеров… Например, как люди реагируют… | Стилизация добавила требования (мемы, конкретные герои), на которые эталон не отвечает |

Итого: 4 искусственные связки, 3 неподтверждённых или неустойчивых эталона, 3 неоднозначных
или вопроса без контекста, 2 случая, когда стилизация исказила вопрос. Вывод для генерации: составные
вопросы по случайной паре документов часто получаются натянутыми. Сущность в паре должна быть общей
по смыслу, а не только по имени.

### Разбиение

Стратифицированное по типу вопроса, seed 42 (`gigarag.gold.stratified_split`): 36 validation / 14 test.
В каждом типе в test 27–30% вопросов (4 из 15, 4 из 15, 3 из 10, 3 из 10).
Подбор параметров в КТ 2–4 делается только на validation, test — для финальных цифр.

### Лексическое разнообразие

70% вопросов переформулированы, 30% оставлены как есть:

| Стиль | Доля | Пример |
|---|---|---|
| опечатки | 18% | «какой теперь прирсо рост силы у tidehunter апосле патча 7.40b» |
| разговорный | 16% | «Чё по билду на Рубика в лейте, что Ваня Золо советует собирать, какой шмот юзать?» |
| короткий запрос | 14% | «Alchemist 7.41 талант радиус взрыва» |
| развёрнутый | 12% | «Я играю на Nature's Prophet и хочу лучше понимать его эффективность…» (медиана 55 слов) |
| имена по-русски и сленгом | 10% | «…с бреин сэпа даёт талант на 25 у бейна после патча 7.37b?» |

Стиль «имена» выдаётся только вопросам с латиницей, остальным вместо него достаётся разговорный.
Поэтому разговорных вопросов больше плана (16% вместо 10%). Опечатки и сленговые имена попали
в test по одному вопросу: сравнивать стили надёжнее на validation.

### Покрытие

- **Типы и документы с ответом.** В среднем 1,5 документа с оценкой 2 у фактического вопроса,
  3,3 у составного, 9,3 у абстрактного. У фактических ответ часто продублирован: правка из патчноута
  пересказана в статье dota2.ru — это и есть риск «один факт в нескольких источниках» из EDA.
  У негативных вопросов документов с оценкой 2 нет, а с оценкой 1 — в среднем 7. Это трудные негативы:
  рядом лежат похожие правки других патчей, и ретривер их найдёт.
- **Источники.** Фактические и составные вопросы опираются на патчноуты (73% и 100% вопросов)
  и статьи dota2.ru. Абстрактные — на Telegram (90% @Dota2, 40% @gabenews) и комментарии.
  У 6 из 15 составных ответ лежит в 3–4 источниках, у 7 — в двух.
- **Патчи.** Вопросы затрагивают 24 из 36 патчей окна. Не покрыты 12 мелких буквенных хотфиксов
  (7.34b–e, 7.35d, 7.37e, 7.38b, 7.39c–e, 7.41a, 7.41c); сильнее всех покрыт крупный 7.41.
- **Негативные вопросы — пяти видов:** патчи до окна корпуса (3), будущий патч 7.42 (2), несуществующий
  герой (1), ложная предпосылка о существующем или выдуманном герое (3), другая игра (1).
- **Пробелы.** Мало вопросов только по комментариям dota2.ru: они в основном служат второй половиной
  составных. Нет вопросов о косметике и турнирах: это кластеры EDA, но не тема корпуса — баланс.

## Baseline без RAG

`scripts/baseline_no_rag.py`: модель отвечает на 36 вопросов validation без контекста (t = 0, seed 42).
Системный промпт задаёт те же границы, что будут у RAG-системы: баланс Dota 2 в патчах 7.34–7.41f.
Вне их, для несуществующего и при незнании модель должна ответить, начав со слов «Не знаю».

Оценка:
- **Отказ** распознаётся без судьи (`patterns.is_abstention`): на негативном вопросе это correct,
  на остальных — abstained. Судья путал отказ с верным ответом.
- **Остальные ответы** судья `gpt-4.1-2025-04-14` (t = 0) сравнивает с эталоном: correct, partial
  или incorrect. На негативном вопросе любые конкретные факты — incorrect.
- **Ручная валидация.** Все 46 вердиктов судьи просмотрены вручную. 6 исправлены на incorrect
  (`gold/baseline_review.json`): судья ставил partial или correct ответам с выдуманными правками,
  если общий вывод совпадал с эталоном.
- **Балл:** correct — 1, partial — 0,5. Две ошибки считаются раздельно: `hallucinated` — неверный
  содержательный ответ на вопрос, у которого ответ есть; `missed_abstention` — содержательный ответ
  на негативный вопрос.

| Модель | Балл | correct | partial | incorrect | abstained |
|---|---|---|---|---|---|
| `gpt-4.1-mini-2025-04-14` | 26,4% | 19,4% | 13,9% | 50,0% | 16,7% |
| `gpt-4.1-2025-04-14` | 26,4% | 22,2% | 8,3% | 50,0% | 19,4% |

Балл по типам вопросов (mini / полная): фактические — 0 / 9,1%, составные — 9,1 / 0%,
абстрактные — 35,7 / 35,7%, негативные — 85,7 / 85,7%.

- **Конкретные правки по версиям модель не знает, но уверенно сочиняет.** На фактических и составных
  вопросах выдуманы 17 ответов из 22 у каждой модели. Именно здесь RAG нужен в первую очередь.
- **Абстрактные проходят частично (36%).** Общие тезисы про мету модель помнит из предобучения,
  но без опоры на корпус ответ остаётся общим, а на трёх вопросах из семи она отказывается.
- **Границы в промпте работают.** На негативных вопросах обе модели отказываются в 6 случаях из 7,
  в том числе про патчи 7.29 и 7.32. Пропущенный отказ — по одному у каждой: mini ответила по памяти
  про 7.32, полная модель описала несуществующего «Phantom Golem» как юнит Book of Shadows.
- **Большая модель не лучше малой.** Генератор для КТ 5 — `gpt-4.1-mini`: качество то же, стоимость ниже.

Судья без ручной проверки завышает оценку: его согласованность и качество проверяются в КТ 5.
На 36 вопросах разница в несколько процентных пунктов между моделями — это шум.
